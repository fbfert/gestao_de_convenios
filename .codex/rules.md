# Regras Permanentes

- Antes de alterar código, leia as specs aplicáveis em `openspec/specs`.
- As specs aprovadas são a fonte de verdade do projeto.
- Nenhuma implementação pode contrariar uma spec aprovada.
- Se código existente e spec entrarem em conflito, registre o conflito antes de alterar.
- Se houver ambiguidade, pare e peça decisão humana.
- Toda funcionalidade nova precisa ter spec criada ou atualizada antes da implementação.
- Toda alteração relevante deve ser validada com `openspec validate` antes de ser considerada concluída.
- No resumo final de qualquer tarefa, registre quais specs foram lidas e quais comandos de validação foram executados.
